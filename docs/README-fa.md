# رُست‌خانهٔ دانه — نسخهٔ MERN

فروشگاه قهوهٔ تخصصی با همان طراحی نسخهٔ اولیه، ولی این بار
داده‌ها از **MongoDB** خوانده می‌شوند و یک **پنل مدیریت** کامل دارد.

- **M**ongoDB + Mongoose — پایگاه داده
- **E**xpress — API
- **R**eact + **Next.js** (App Router) — سایت و پنل، با رندر سمت سرور
- **N**ode.js — اجرا

---

## 🚀 راه‌اندازی سریع

### پیش‌نیاز
MongoDB باید روی این کامپیوتر نصب و **روشن** باشد.
برای بررسی، در پاورشل بزنید:

```powershell
Get-Service MongoDB
```

اگر `Running` نبود، با دسترسی مدیر روشنش کنید:

```powershell
net start MongoDB
```

### نصب و پر کردن پایگاه داده

در پوشهٔ اصلی پروژه (`Ghahve`) یک بار این را بزنید:

```bash
npm run setup
```

این کار دو چیز را انجام می‌دهد: نصب پکیج‌های هر سه بخش (سرور، سایت و
منطق مشترک — با یک `npm install`)، و ریختن **۱۰۶ کالا** (۳۲ قهوه، ۴۰
ابزار، ۳۴ پودر) داخل پایگاه داده به‌همراه ساختن حساب مدیر.

### اجرا

```bash
npm run dev
```

حالا:

| آدرس | چیست |
|---|---|
| <http://localhost:3000> | فروشگاه |
| <http://localhost:3000/admin> | پنل مدیریت |
| <http://localhost:3000/track> | پیگیری سفارش |
| <http://localhost:4000/api> | API |

> `npm run dev` دو چیز را با هم بالا می‌آورد: سایت روی ۳۰۰۰ و API روی
> ۴۰۰۰. در پنجرهٔ خط فرمان پیام‌ها با برچسب `web` و `api` از هم جدا
> می‌شوند. شما فقط با ۳۰۰۰ کار دارید؛ سایت خودش از API می‌خواند.

> پیام‌های خط فرمان (سرور و seed) **انگلیسی** هستند، چون پنجرهٔ cmd
> ویندوز حروف فارسی را `?` چاپ می‌کند. متن‌هایی که مشتری در سایت
> می‌بیند و پیام‌های خطای پنل، همچنان فارسی‌اند.

### اگر خطای `Port 4000 is already in use` دیدید

یعنی یک نسخهٔ دیگر از سرور هنوز باز است — مثلاً پنجرهٔ قبلی را بسته‌اید
ولی فرآیندش زنده مانده. در پاورشل:

```powershell
Get-NetTCPConnection -LocalPort 4000 -State Listen | Select-Object OwningProcess
Stop-Process -Id <عددی که بالا آمد> -Force
```

بعد دوباره `npm run dev` بزنید. خودِ پیام خطا هم همین دو دستور را
نشان می‌دهد.

## 🔑 ورود به پنل مدیریت

**آدرس پنل: <http://localhost:3000/admin>**

فقط همین آدرس را در مرورگر باز کنید. اگر وارد نشده باشید،
خودش صفحهٔ ورود را نشان می‌دهد.

نام کاربری و رمز اولیه:

```
نام کاربری:  admin
رمز عبور:    change-me
```

> ⚠️ **همین اول رمز را عوض کنید.**
> در پنل، از منوی بالا روی **«رمز عبور»** بزنید.

راه‌های دیگر رسیدن به پنل:
- در فوتر یا هر جای سایت لینکی به پنل نگذاشته‌ایم (عمدی — تا مشتری‌ها نبینند).
- از داخل پنل، دکمهٔ **«دیدن سایت ↗»** شما را به فروشگاه برمی‌گرداند.

## 🛠 پنل مدیریت چه کارهایی می‌کند

### ۱) کالاها (`/admin/items`)
- سه زبانهٔ **قهوه / ابزار / پودر**
- **افزودن** کالای تازه با فرم کامل و **پیش‌نمایش زندهٔ کارت**
  (همان کارتی که مشتری در سایت می‌بیند، همان لحظه کنار فرم ساخته می‌شود)
- **ویرایش** هر کالا: نام، خاستگاه، مشخصات، ویژگی‌ها، قیمت، دسته، برچسب، ترتیب
- **معرفی کامل**: از کجا می‌آید، در فنجان چه می‌چشید، و پیشنهاد ما برای
  دم کردنش — همان سه بخشی که در پنجرهٔ «دربارهٔ این قهوه» دیده می‌شود
- **پروفایل طعمی**: برچسب‌هایی مثل شیرین، میوه‌ای، شکلاتی — پایهٔ بخش
  «چه طعمی دوست دارید؟»
- **میکس**: می‌شود یک قهوه را از چند دانه ساخت، درصد هرکدام را تعیین کرد،
  و بازهٔ مجاز (کمینه/بیشینه) گذاشت تا مشتری فقط در همان بازه جابه‌جا کند.
  دانه‌های «قابل افزودن» را هم مشخص می‌کنید
- **ویترین**: اینکه کالا در «پیشنهاد ما» بیاید، همیشه در «پرفروش‌ها»
  بالا بماند، یا هیچ‌وقت آنجا نیاید
- **حذف** با یک مرحله تأیید (تا اشتباهی پاک نشود)
- کلید **روشن/خاموش**: کالا در پایگاه داده می‌ماند ولی در سایت دیده نمی‌شود
- جست‌وجو در نام، شناسه و خاستگاه

### ۲) تصویرها
هر کالا به‌صورت خودکار یک **طرح اختصاصی** می‌گیرد (همان دانه‌ها، ابزارها و
پودرهایی که در سایت می‌بینید — با کد کشیده می‌شوند، نه فایل عکس).

اگر **عکس واقعی** دارید، در فرم کالا بخش «تصویر کارت» آپلودش کنید؛
همان عکس جای طرح خودکار می‌نشیند. با زدن «برداشتن عکس» دوباره به
طرح خودکار برمی‌گردد و فایل عکس هم از روی دیسک پاک می‌شود.

- فرمت‌های مجاز: JPG, PNG, WebP, AVIF, GIF, SVG
- حداکثر حجم: ۴ مگابایت
- محل ذخیره: `server/uploads/`

### ۳) سفارش‌ها (`/admin/orders`)
- همهٔ سفارش‌ها با نام، تلفن، نشانی و نحوهٔ آسیاب
- نحوهٔ آسیاب **برای هر ردیف جداگانه** ثبت می‌شود؛ اگر مشتری میکس
  دلخواه ساخته باشد، نسبت دانه‌هایش هم در همان ردیف می‌آید
- فیلتر بر اساس وضعیت: تازه / در حال آماده‌سازی / تحویل شده / لغو شده
- تغییر وضعیت با یک کلیک

### ۴) گزارش‌ها (`/admin/reports`)
گزارش فروش و **پشتیبان‌گیری از سفارش‌ها**.

- خلاصهٔ فروش به تفکیک **روزانه / هفتگی / ماهانه / سالانه**
- بازه‌ها روی **تقویم شمسی** و به وقت تهران بسته می‌شوند — «مرداد»
  یعنی دقیقاً مرداد، نه ماه میلادی. هفته هم از **شنبه** شروع می‌شود.
- با کلیک روی هر ردیف، فهرست پایین همان بازه را نشان می‌دهد
- با کلیک روی هر سفارش، **همهٔ جزئیات آن خرید** باز می‌شود:
  ردیف‌ها، وزن، نحوهٔ آسیاب، ترکیب میکس، قیمت واحد و اطلاعات مشتری
- جست‌وجو در شمارهٔ سفارش، نام، تلفن و نام کالا
- سفارش‌های **لغوشده در فروش حساب نمی‌شوند** ولی در فهرست و در
  فایل پشتیبان می‌مانند

**سه نوع خروجی** — هر سه دقیقاً همان بازه/وضعیت/جست‌وجوی انتخاب‌شده
را می‌گیرند:

| فایل | به چه دردی می‌خورد |
|---|---|
| اکسل: یک ردیف هر سفارش | مرور سریع فروش در اکسل |
| اکسل: ریز کالاها | یک ردیف برای هر کالای هر سفارش — برای حسابداری |
| پشتیبان کامل JSON | **نسخهٔ پشتیبان واقعی** — همه‌چیز بی‌کم‌وکاست |

> اگر روزی پایگاه داده از بین برود، فایل **JSON** همان چیزی است که
> سفارش‌ها را از رویش برمی‌گردانید. فایل‌های اکسل برای خواندن‌اند،
> نه برای بازگرداندن. پس هر از چندی یک JSON بگیرید و جای امن نگه دارید.

فایل‌های CSV با BOM ساخته می‌شوند تا اکسلِ فارسی درست بازشان کند، و
سلولی که با `=` شروع شود بی‌اثر می‌شود تا اکسل آن را فرمول نگیرد.

### ۵) محتوای سایت (`/admin/content`)
همهٔ متن‌های صفحهٔ اصلی از اینجا عوض می‌شوند — هر بخش دکمهٔ ذخیرهٔ
خودش را دارد و یک دکمهٔ «بازگشت به متن اولیه»:

| بخش | چه چیزی را می‌سازد |
|---|---|
| چرا از ما بخرید | بخش متقاعدکنندهٔ بالای صفحه، با نماد برای هر دلیل |
| چه طعمی دوست دارید؟ | پیشنهاد قهوه بر پایهٔ سلیقه («اگر شیرینی دوست دارید…») |
| پیشنهاد روز و پرفروش‌ها | عنوان‌های دو بخش ویترین |
| میکس‌های ویژه | عنوان و راهنمای بخش میکس |
| باشگاه مشتریان | متن‌ها و اینکه ایمیل و سلیقه پرسیده شود یا نه |
| دربارهٔ ما | داستان، عددها، نشانی و ساعت کار |
| گزینه‌های آسیاب | همان فهرستی که روی کارت هر قهوه و در سبد دیده می‌شود |

### ۶) باشگاه مشتریان (`/admin/club`)
- فهرست اعضا با نام، موبایل، ایمیل، سلیقه و تاریخ عضویت
- جست‌وجو و حذف
- **خروجی CSV** برای دادن به سامانهٔ پیامک یا خبرنامه

### ۷) رمز عبور (`/admin/settings`)
تغییر **نام کاربری** و **رمز عبور**.
بعد از تغییر رمز، هر دستگاه دیگری که با رمز قبلی وارد شده بود
به‌طور خودکار از پنل بیرون می‌آید.

## 💾 دربارهٔ پایگاه داده

هر سه نوع کالا در **یک مجموعهٔ واحد** (`items`) ذخیره می‌شوند و با
فیلد `kind` از هم جدا می‌شوند. این باعث می‌شود پنل مدیریت و API
برای هر سه یکی باشد و جای کمتری برای خطا بماند.

نکته‌های مهمی که رعایت شده:

- **شناسهٔ یکتا:** هیچ دو کالایی نمی‌توانند `slug` یکسان داشته باشند.
- **اعتبارسنجی وابسته به نوع:** مثلاً دستهٔ «آسیاب» را نمی‌شود به یک قهوه داد.
- **قیمت‌ها هنگام ثبت سفارش دوباره از پایگاه داده خوانده می‌شوند** —
  عددی که از مرورگر می‌آید اصلاً استفاده نمی‌شود.
- **سفارش‌ها قیمت لحظهٔ خرید را نگه می‌دارند** — اگر بعداً قیمت را عوض کنید،
  فاکتورهای قدیمی دست‌نخورده می‌مانند.
- **سبد خرید مشتری خودش را تمیز می‌کند** — اگر کالایی را حذف یا پنهان کنید،
  از سبد کسانی که آن را داشتند برداشته می‌شود.
- **رمز مدیر با bcrypt هش می‌شود** و هیچ‌وقت خام ذخیره یا برگردانده نمی‌شود.

### دستورهای مفید

```bash
npm run seed          # کالاهای جدید را اضافه می‌کند، به ویرایش‌های شما دست نمی‌زند
npm run seed:reset    # ⚠ همه‌چیز را پاک و از نو می‌سازد (ویرایش‌ها از بین می‌رود)
```

## 🌐 اجرا در حالت تولید

```bash
npm run build     # ساخت خروجی بهینهٔ سایت (به اینترنت نیاز دارد — فونت‌ها)
npm start         # هر دو سرور: سایت روی ۳۰۰۰، API روی ۴۰۰۰
```

بعدش سایت و پنل روی <http://localhost:3000> اند و API روی
<http://localhost:4000>.

> **چرا دو سرور و نه یکی؟** پیش‌تر یک سرور هم سایت را می‌داد و هم API. از
> وقتی سایت به Next.js منتقل شده (برای اینکه گوگل و تلگرام متنِ صفحه‌ها
> را ببینند)، سایت سرور خودش را دارد. برای شما فرقی نمی‌کند: همان
> `npm run dev` و همان `npm start` هر دو را با هم بالا می‌آورند.

## ☁️ اگر خواستید به MongoDB Atlas وصل شوید

فقط یک خط در `server/.env` عوض می‌شود:

```env
MONGODB_URI=mongodb+srv://<user>:<pass>@<cluster>.mongodb.net/ghahve
```

بعد `npm run seed` را بزنید تا داده‌ها آنجا هم ساخته شوند.

## ⚙️ تنظیمات `server/.env`

| کلید | کار |
|---|---|
| `PORT` | پورت سرور (پیش‌فرض ۴۰۰۰) |
| `MONGODB_URI` | آدرس پایگاه داده |
| `JWT_SECRET` | کلید امضای توکن ورود — تصادفی ساخته شده، عوضش نکنید |
| `TOKEN_HOURS` | چند ساعت نشست مدیر باز بماند |
| `ADMIN_USERNAME` / `ADMIN_PASSWORD` | فقط بار اولِ seed استفاده می‌شوند |
| `CLIENT_ORIGIN` | آدرس مجاز برای CORS — در حالت تولید **اجباری** است |
| `SITE_URL` | آدرس عمومی سایت؛ پایهٔ لینک‌های `sitemap.xml` |
| `RATE_LIMIT_*` | سقف تلاش برای ورود، ثبت سفارش و پیگیری |
| `TRUST_PROXY` | اگر پشت nginx یا کلادفلر هستید، ۱ کنید |

سایت هم فایل تنظیمات خودش را دارد (`web/.env.example` را به
`web/.env.local` کپی کنید):

| کلید | کار |
|---|---|
| `API_URL` | آدرس سرور — سایت موقع ساختن صفحه از آن می‌خواند |
| `NEXT_PUBLIC_SITE_URL` | آدرس عمومی سایت؛ باید با `SITE_URL` یکی باشد |
| `NEXT_PUBLIC_OG_IMAGE` | تصویر پیش‌نمایش لینک، وقتی کالا عکس ندارد |

> **دو نکته که به‌سادگی اشتباه می‌شوند:**
>
> ۱) `SITE_URL` و `NEXT_PUBLIC_SITE_URL` باید **دقیقاً یکی** باشند. یکی
> آدرس داخل نقشهٔ سایت را می‌سازد و دیگری آدرس رسمی هر صفحه را؛ اگر فرق
> کنند گوگل دو نسخه از یک صفحه می‌بیند.
>
> ۲) هر دوی آن‌ها — و `CLIENT_ORIGIN` — آدرس **سایت** اند (پورت ۳۰۰۰)،
> نه آدرس سرور API (پورت ۴۰۰۰). حتی آن‌که در `server/.env` نوشته می‌شود.
> بازدیدکننده صفحه‌ها را از ۳۰۰۰ می‌گیرد.

> فایل `.env` را جایی منتشر نکنید. `.env.example` نسخهٔ بی‌خطرِ آن است.
